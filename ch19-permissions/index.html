第 19 章 · Part 7：進階技巧

Permissions 模式

Claude Code 不是無限制地執行任何事。四種權限模式定義了它能做什麼，以及什麼需要你點頭確認。

四種權限模式

← 審查優先　　　　　　　自動化優先 →
plan
先規劃
列出步驟
你批准才執行
初次使用推薦
default
安全操作自動執行
危險操作需確認
⭐ 日常開發
auto
多數操作自動批准
高信任模式
CI / 腳本
bypass
跳過所有確認步驟
包含危險操作
⚠ 隔離環境

切換模式

bash 
# 啟動時指定模式
claude --permission-mode plan   # 規劃模式
claude --permission-mode auto   # 自動模式

# 在互動模式中切換
You: /permissions

Plan 模式：先看後做

在 plan 模式下，Claude 會描述它打算做什麼，等你批准才執行：

互動模式（plan 模式） 
You: 重構 src/auth/ 使用新的 JWT 格式

Claude: 我的執行計劃：
  1. 讀取 src/auth/jwt.ts（讀取操作）
  2. 修改 verifyToken 函式（寫入操作）⚠️
  3. 更新 src/middleware/auth.ts（寫入操作）⚠️
  4. 執行 npm test（執行操作）⚠️

確認執行這些操作？[y/N]
💡
Plan 模式的最佳使用時機

第一次讓 Claude 處理重要任務時，先用 plan 模式看它的計劃，確認沒有意外操作再切回 default 模式執行。

自訂允許清單

用 /permissions 永久允許特定操作，不再每次確認：

互動模式 
You: /permissions

Permission settings:
  ✓ Read files          always allowed
  ✓ Write files         ask first
  ✓ Run npm scripts     always allowed  ← 你設定的
  ✗ git push            always denied   ← 你設定的
  ✓ Bash commands       ask first

在 settings.json 設定

~/.claude/settings.json 
{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)"
    ],
    "deny": [
      "Bash(git push *)",
      "Bash(rm -rf *)"
    ]
  }
}

CI/CD 中使用 bypass 模式

GitHub Actions / CI 
# CI 環境中完全自動化
claude --print --permission-mode bypass   "執行測試套件，修復所有失敗的測試，並提交變更"
⚠️
bypass 模式風險

bypass 模式下，Claude 不會在執行危險操作前請求確認。只在完全受控的環境（如 CI/CD 或 Docker 沙箱）中使用。不建議在本機日常開發使用。
