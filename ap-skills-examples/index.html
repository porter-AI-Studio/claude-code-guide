附錄 E · Skills 實戰

Skills 實戰手冊

四個真實 Skill 的完整使用說明——從 UI 設計到 Git 部署，從影片轉錄到 Obsidian 整理，每個都是能立即上手的工作流。

一、UI/UX 前端設計：/frontend-design

/frontend-design 生成高品質前端介面，核心特色是刻意避免「AI 味」—— 不用通用字體（Inter、Roboto）、不用紫色漸層白底、不用千篇一律的 card + grid 佈局。 每次呼叫都要選定一個明確的美學方向，貫徹到底。

觸發範例 
You: /frontend-design
請幫我設計一個 API 健康度儀表板。使用者是後端工程師，
需要看到 API 延遲分佈、錯誤率、最近 20 筆請求記錄。

Skill 執行前的設計思考流程：

  • Purpose（目的）：使用者是誰？介面解決什麼問題？
  • Tone（風格）：選一個極端——工業極簡、復古終端機、報紙排版、奢華精緻…然後貫徹到底
  • Differentiation（記憶點）：這個介面讓人記得的是什麼？
指定風格的觸發範例 
You: /frontend-design
設計一個 SaaS 產品登入頁。目標用戶是企業 IT 管理員。
風格：工業感極簡，黑灰配色，資訊密度高，像 Bloomberg Terminal。
💡
讓 Claude 大膽選擇風格

如果你不指定風格，Claude 會自主選定方向。建議把需求說清楚（使用者、內容、情緒）但不限制風格，讓 Skill 選最適合的——往往比你指定的更驚豔。

二、Git 部署工作流

2-1 一鍵部署：/deploy-porter-book

封裝完整的「本地建置 → Git commit → push → 等待 GitHub Actions → 確認上線」流程。 核心保護：若本地 build 失敗，腳本立刻停止，不會 push 壞掉的程式碼。

觸發範例 
You: /deploy-porter-book
# 或帶 commit message：
You: /deploy-porter-book 新增 Hooks 章節實戰範例

執行流程（5 步驟）：

  1. 確認 git status，若無變更則停止
  2. npm run build — 失敗則停止，不 push
  3. git add . && git commit && git push
  4. 用 opencli browser 監控 GitHub Actions 進度（最多等 3 分鐘）
  5. 截圖確認網站已上線
ℹ️
改成自己的部署 Skill

複製 deploy-porter-book 的結構，改成你自己的專案路徑、repo URL、commit message 格式，就有了屬於你的一鍵部署 Skill。

2-2 產生 .gitignore：/gitignore

偵測專案技術棧，自動產生完整 .gitignore。最重要的：會掃描目前已被 Git 追蹤但應該被忽略的敏感檔（.env、*.key），並提示處理方式。

觸發範例 
You: /gitignore
# Claude 自動偵測到：Node.js + Docker + Python
# 產生完整 .gitignore 後報告：
# ⚠ .env.local 已被 Git 追蹤 → 建議執行 git rm --cached .env.local

三、影片轉逐字稿：/local-video-note

把本機影片轉成 Obsidian 雙語筆記的完整自動化流程——一個指令涵蓋音訊萃取、語音辨識、翻譯、建立筆記。

指令語法 
/local-video-note <影片路徑> [--start HH:MM:SS] [--end HH:MM:SS]

# 整部影片
/local-video-note "C:\Users\porte\Videos\demo.mp4"

# 只處理特定段落（5:00 到 15:00）
/local-video-note demo.mkv --start 00:05:00 --end 00:15:00

完整流程

1 驗證輸入：確認檔案存在、格式支援（mkv / mp4 / mp3 / wav / ...）
2 ffmpeg 萃取音訊 → 16kHz mono PCM WAV（Whisper 最佳輸入）
3 Whisper 語音轉文字：GPU（whisper-cli + Vulkan）優先，無 GPU 則 CPU fallback
4 SRT → 雙語表格：AI 逐句填入中英對照翻譯
5 建立 Obsidian 筆記：含 VID 編號、時間戳記、完整雙語逐字稿

核心指令詳解

Step 2：ffmpeg 萃取 16kHz WAV（Whisper 標準格式） 
# 確保輸出目錄存在
New-Item -ItemType Directory -Force -Path "C:\video\process_audio" | Out-Null

# 整部影片萃取音訊
ffmpeg -y -i "demo.mp4" -vn -ar 16000 -ac 1 -c:a pcm_s16le "C:\video\process_audio\demo.wav"

# 裁切時間段（5:00 到 15:00）
ffmpeg -y -i "demo.mp4" -ss 00:05:00 -to 00:15:00 -vn -ar 16000 -ac 1 -c:a pcm_s16le "demo.wav"
Step 3a：whisper-cli（GPU / Vulkan 模式） 
$whisperCli = "C:\Users\porte\dev\whisper.cpp\build\bin\whisper-cli.exe"
$modelPath  = "C:\Users\porte\dev\whisper.cpp\models\ggml-large-v3-turbo.bin"
$wavPath    = "C:\video\process_audio\demo.wav"
$outPrefix  = "C:\video\process_audio\demo"

& $whisperCli -m $modelPath -f $wavPath -l zh -otxt -osrt -of $outPrefix -pp --no-speech-thold 0.6
# 輸出：demo.txt（純文字）、demo.srt（含時間戳記字幕）
Step 3b：faster-whisper CPU Fallback（無 GPU 時） 
uv run --with faster-whisper python transcribe_audio.py demo.wav --model medium --language zh

性能參考（large-v3-turbo + Intel Arc / Vulkan）：

音訊長度GPU 時間CPU 時間（估算）
10 分鐘~2–3 分鐘~10–15 分鐘
1 小時~12–18 分鐘~60–90 分鐘

四、Obsidian Tags 整理：/obsidian-markdown

/obsidian-markdown Skill 覆蓋完整 Obsidian Flavored Markdown 語法。 其中 tags 整理是最高頻的使用場景：統一命名規範、建立階層結構、清理孤立 tag。

Tags 語法速查

Frontmatter tags（推薦） 
---
title: "API 設計規範"
tags:
  - backend
  - api/rest
  - api/graphql
  - project/gyro-2026
---
Inline tags（行內標記） 
這份文件涵蓋 #backend 開發核心，特別是 #api/rest 設計原則。

> [!tip] 最佳實踐
> 使用巢狀 tag（如 #project/gyro-2026）建立階層，比平鋪更容易在 Obsidian Graph 中篩選。

Tags 整理工作流

讓 Claude Code 協助審計 Vault 的 tag 結構：

觸發範例 
You: /obsidian-markdown
請幫我審計 C:\Obsidian\vault 下所有筆記的 tag 使用情況：
1. 列出所有 tag 及出現次數（由多到少）
2. 找出只出現一次的孤立 tag（可能是拼寫錯誤）
3. 建議合併同義 tag 的方案
PowerShell — 快速統計 Vault Tags 
$tags = @{}
Get-ChildItem "C:\Obsidian\vault" -Recurse -Filter "*.md" | ForEach-Object {
    $inFm = $false
    foreach ($line in (Get-Content $_.FullName)) {
        if ($line -eq "---") { $inFm = -not $inFm }
        if ($inFm -and $line -match "^  - (.+)") { $tags[$matches[1]]++ }
    }
}
$tags.GetEnumerator() | Sort-Object Value -Descending | Format-Table Name, Value -AutoSize

常見整理動作：

  • 批次重命名：把 #AI、#ai、#artificial-intelligence 統一為 #ai
  • 建立階層：#python、#javascript → #lang/python、#lang/js
  • 清理孤立 tag：只出現一次的 tag 通常是拼寫錯誤，需人工確認
  • 自動補 tag：要求 Claude 掃描沒有 tag 的筆記，根據內容自動補上
ℹ️
Obsidian CLI 快速統計

若安裝了 Obsidian CLI 工具，可直接執行：
obsidian tags sort=count counts
列出所有 tag 並依使用頻率排序，比手動掃描更精確，也支援 backlinks 查詢。
