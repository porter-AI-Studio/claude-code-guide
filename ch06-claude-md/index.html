第 6 章 · Part 3：設定與記憶

CLAUDE.md

Claude Code 的「說明書」。每次對話開始前自動載入，告訴 Claude 你是誰、你的專案長什麼樣、你希望它怎麼做事。

什麼是 CLAUDE.md？

CLAUDE.md 是一個純 Markdown 文件，在每次 Claude Code 啟動時自動載入到上下文。 你不需要每次都解釋「我的專案用 TypeScript」「回答請用繁體中文」「不要自動 push git」—— 寫在 CLAUDE.md 一次，它就永遠記得。

把它想成你僱用新工程師時給他的入職文件。

四層架構：哪個檔案管哪個範圍

層級位置範圍適合放什麼
全域個人 ~/.claude/CLAUDE.md 所有專案 語言偏好、個人縮寫、時區、通用規則
專案共享 ./CLAUDE.md 當前專案（git 追蹤） 技術棧、架構說明、team 規範、Build 指令
本地私有 ./CLAUDE.local.md 當前專案（不 commit） 個人開發偏好、本機路徑、私人 API Key 說明
子目錄 ./src/CLAUDE.md 特定目錄 該模組的特殊規則（如 API 目錄的驗證規則）

CLAUDE.md 範圍層次（越內層越優先）

優先順序

Claude 會全部載入，不是覆蓋——所有層級的 CLAUDE.md 都會被讀取。如果有衝突，越具體的（子目錄層）越優先。建議把通用規則放全域，專案相關放專案根目錄。

快速產生 CLAUDE.md

讓 Claude 自動分析你的專案並生成初始版：

You: /init

Claude:
Scanning project directory...
Reading package.json...
Reading README.md...
✓ Created CLAUDE.md with detected tech stack (Next.js, TypeScript).
I've generated a default `CLAUDE.md` file for you based on the project structure. Please review and add any specific personal preferences or rules.

Claude 會掃描你的 package.json、README.md、目錄結構，自動填寫常用欄位。之後再手動補充你的個人偏好。

標準結構範本

CLAUDE.md 
# 專案名稱

## 專案簡介
一句話說明這個專案是什麼、做什麼用的。

## 技術棧
- 語言：TypeScript 5.x
- 框架：Next.js 15 / Fastify
- 資料庫：PostgreSQL + Prisma ORM
- 測試：Vitest + Testing Library

## 常用指令
- Build：`npm run build`
- Dev server：`npm run dev`
- 測試：`npm test`
- 型別檢查：`npm run typecheck`

## 架構說明
- `src/api/` — API routes（Fastify plugins）
- `src/services/` — 商業邏輯
- `src/db/` — Prisma schema 與 migrations

## 開發規範
- 使用 TypeScript strict mode
- 函式盡量控制在 30 行以內
- 所有 async 函式必須有 error handling

## 注意事項
- 不要自動 push 到 main branch
- 不要修改 package.json 的 version 欄位

實際範例：個人全域設定

以下是一份真實的 ~/.claude/CLAUDE.md 個人全域設定：

~/.claude/CLAUDE.md 
# 個人設定

## 身分
你是我的 AI 助理與分身。

## 回應語言
請用繁體中文回應，專有名詞（API、CLI、Git 等）保留英文。

## 縮寫對照
- `ag` = Antigravity（主要專案）
- `obs` = Obsidian（筆記工具）
- `cc` = Claude Code（這個工具本身）

## 時區
永遠使用台北時間（Asia/Taipei, UTC+8）。
進行日期計算前先執行 `date` 確認系統時間。

## 程式碼風格
- 預設使用 TypeScript
- 非必要不加 comment（好的命名自己說話）
- 不要加 try-catch 在永遠不會 throw 的地方

## 安全規則
- 永遠不要 commit .env 或任何含有 secret 的檔案
- 不要在程式碼中 hardcode API key

Import 語法：拆分管理

當 CLAUDE.md 內容太多時，用 @ 語法拆分成多個檔案：

CLAUDE.md 
# 主設定檔

## 通用規範
@~/.claude/rules/security.md
@~/.claude/rules/coding-style.md

## 專案架構
詳見 @README.md 與 @docs/architecture.md

## API 開發規範
@src/api/CLAUDE.md
ℹ️
Import 規則

支援相對路徑（./docs/rules.md）與絕對路徑（~/.claude/rules.md）。最多 4 層遞迴 import。首次遇到新的外部 import 路徑時，Claude Code 會請你確認是否允許讀取。

撰寫建議

  • 每個 CLAUDE.md 控制在 200 行以內——太長會降低 Claude 對重要規則的注意力
  • 寫具體可驗證的規則——「使用 2 格縮排」比「好好格式化程式碼」有效
  • 用 Markdown 標題組織結構——方便 Claude 快速找到對應的規則
  • HTML 註解不消耗 token——維護者筆記可用 <!-- 說明 -->，不影響 Claude 的 context
  • 定期更新——隨著專案演進，過時的規則比沒有規則更糟
