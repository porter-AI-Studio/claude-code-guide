第 14 章 · Part 5：Skills

自己寫 Skill

Skill 就是一個 Markdown 檔案。告訴 Claude「什麼時候啟動」以及「要做什麼」，就完成了。

Skill 的本質

Skill 是放在 ~/.claude/skills/ 目錄下的 .md 檔案。 Claude Code 在每次對話開始時掃描這個目錄，當使用者的請求符合 TRIGGER 條件時，自動套用對應的 Skill。

基本結構

~/.claude/skills/my-skill.md 
---
description: 這個 Skill 做什麼的一句話說明
trigger: 什麼情況下自動觸發（給 Claude 判斷用）
argument-hint: 使用者需要提供的參數說明（可選）
---

# Skill 名稱

## 執行流程
1. 步驟一：...
2. 步驟二：...
3. 步驟三：...

## 輸出格式
說明最終要產出什麼格式的結果。

## 注意事項
- 特殊限制或邊界情況

實戰範例：本地影片轉 Obsidian 筆記

這是一個真實使用的 Skill：把本地影片檔案轉成帶時間軸的 Obsidian 筆記。

~/.claude/skills/local-video-note.md 
---
description: 擷取本地影片音訊、Whisper 語音轉文字，自動建立 Obsidian 雙語影片筆記。
trigger: 當使用者提到本地影片轉文字、影片筆記、local video 等關鍵字時使用
argument-hint: 影片檔案路徑（必填），開始時間與結束時間（可選，格式 HH:MM:SS）
---

# Local Video Note

## 執行流程

1. **確認參數**：取得影片路徑，確認檔案存在
2. **裁切音訊**（若有指定時間範圍）：
   使用 ffmpeg 擷取指定時間段
3. **轉換格式**：ffmpeg 將影片音訊轉為 WAV（16kHz, mono）
4. **語音辨識**：執行 faster-whisper 進行轉錄
   - 語言偵測：自動
   - 輸出：帶時間戳記的文字段落
5. **建立筆記**：在 Obsidian vault 建立 YYYY-MM-DD-影片名稱.md
   - 包含影片路徑、時間範圍、全文逐字稿
   - 若為英文：產生中英雙語對照

## 輸出格式
Obsidian Markdown，存放於 C:\Obsidian\vault\影片筆記\

## 注意事項
- 需要系統安裝：ffmpeg、faster-whisper
- GPU 加速：若有 NVIDIA GPU，自動使用 CUDA

使用方式：

互動模式 
# 整個影片
You: /local-video-note C:Videosmeeting-2026-06-04.mp4

# 指定時間段（只處理 5:00 到 12:30）
You: /local-video-note C:Videosconference.mp4 --start 00:05:00 --end 00:12:30

更多 Skill 範例結構

範例：每日工作計畫

~/.claude/skills/daily-plan.md 
---
description: 根據今日日誌和 TODO，生成今日工作計畫
trigger: 當使用者說「今日計畫」「daily plan」「今天要做什麼」時觸發
---

# Daily Plan

## 流程
1. 讀取 Obsidian 今日工作日誌（若存在）
2. 搜尋 TODO.md 中未完成項目
3. 列出今日建議優先順序（P1/P2/P3）
4. 輸出為 Obsidian 格式，寫入今日日誌開頭

範例：Dify API 指令產生器

~/.claude/skills/dify-api-cmd.md 
---
description: 根據描述產生對應的 Dify API curl 指令
trigger: 當使用者要呼叫 Dify API、測試 Dify endpoint 時觸發
---

# Dify API Command Generator

## 流程
1. 確認 API 類型（Chat / Completion / Agent）
2. 讀取 .env 中的 DIFY_API_KEY
3. 根據描述產生完整的 curl 指令（含 headers、body）
4. 同時產生 PowerShell 版本（Invoke-RestMethod）

Skills 放置位置

位置範圍適用情境
~/.claude/skills/個人全域個人工作流程，所有專案適用
.claude/skills/專案級特定專案的標準流程，可 git commit 共享
💡
寫好 TRIGGER 是關鍵

TRIGGER 是給 Claude 看的描述，說明什麼情況下應該套用這個 Skill。寫越具體越好，例如「當使用者提到本地影片轉文字、/local-video-note 指令、影片筆記等關鍵字時」。模糊的 TRIGGER 會導致 Skill 被誤觸發。

Skill 的真正價值：從對話中長出來

Skill 最有價值的誕生方式，不是從零開始設計，而是在你跟 Claude Code 的日常對話中自然浮現—— 當你發現某個工作流程做完之後覺得「這個以後還會用到」，那就是該封裝成 Skill 的時機。

封裝 Skill 的最佳時機
  • 這個操作你每週至少做一次，每次都需要解釋一長串背景
  • 你剛完成一個複雜任務，覺得「如果下次有模板就好了」
  • 這個流程涉及你特定的工具組合（特定路徑、特定格式、特定慣例）
  • 你從網路下載了別人的 Skill，但它跟你的環境有差異需要調整

把對話變成 Skill 的流程

從對話到 Skill（示範） 
# 你跟 CC 完成了一個有價值的任務之後：
You: 我們剛才做的這個「讀取 Excel → 彙整成週報 → 寫入 Obsidian」流程很有用，
     請把它封裝成一個 Skill，儲存到 ~/.claude/skills/weekly-report.md

Claude: 好的，我會把完整流程、參數說明、輸出格式整理成 SKILL.md...
# ↑ Claude 直接幫你寫好 Skill 檔案

讓 Skill 不斷進化

Skill 不是寫一次就鎖死的——它應該隨你使用習慣的改變而進化。 每次執行完 Skill 覺得哪裡不順、哪裡可以更精確，直接告訴 CC 修改 Skill 本身：

進化 Skill（示範） 
You: /weekly-report

（執行完之後）
You: 這個 Skill 的摘要格式我想改成條列式，不要段落文字。
     而且輸出路徑要改成 C:\Obsidian\vault\週報\，請更新 Skill 檔案。

Claude: 好的，已更新 ~/.claude/skills/weekly-report.md：
✓ 摘要改為條列式
✓ 輸出路徑更新
💡
Skill 越用越好用，這就是複利

每一次修改都讓 Skill 更貼近你的工作習慣。三個月後，你有了一套完全為你量身打造的 Skill 工具箱—— 寫程式、寫文章、做影音、做報告，每個高頻任務都有對應的 Skill，啟動指令一秒觸發， 不需要每次從頭解釋背景。這就是 AI 原生工作流的複利效應。

下載別人的 Skill 也要進化

從 GitHub 下載的專家 Skill（例如 frontend-design、deep-research）通常假設通用環境。 拿到之後，第一步是「本地化」：把路徑、慣例、輸出格式改成符合你的工作環境。

本地化下載的 Skill 
You: 我把 frontend-design skill 下載到 ~/.claude/skills/ 了，
     請閱讀這個 skill，並做以下調整：
     1. 預設使用 Vue 3 + Vite（原本是 React）
     2. 輸出目錄改到 C:\VSCode_Proj\frontend-output\
     3. 在設計思考流程加入「必須符合公司設計規範 style-guide.md」這一步

Claude: 好的，已更新 frontend-design Skill...
