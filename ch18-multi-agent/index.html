第 18 章 · Part 7：進階技巧

多 Agent 協作

一個 Claude 不夠用？派出多個 subagent 並行處理，各司其職，最後匯整結果。

什麼是 Subagent？

Claude Code 可以在同一個 session 中派出子代理（subagent）—— 每個 subagent 是獨立的 Claude 實例，有自己的訊息歷史、工具集和任務目標。 主代理（orchestrator）負責分工協調，subagent 負責執行。

MULTI-AGENT 協作架構

🎯 Orchestrator（主代理）分工 · 協調 · 匯整結果
↙ /fork↓ /fork↘ /fork
subagent-1
src/auth/ 重構
running
subagent-2
src/api/ validation
running
subagent-3
README 更新
done
↗ result↑ result↖ result
📊 等待所有子任務完成，匯整結果回報

使用 /fork 派出背景任務

互動模式 
# 在背景派出 subagent 執行獨立任務
You: /fork 分析 src/api/ 目錄的安全性漏洞，完成後回報結果

# 主對話繼續，subagent 在背景跑
You: 現在我們來重構 src/services/ 的錯誤處理

# 查看背景任務狀態
You: /tasks

使用 /background 背景執行

互動模式 
# 把目前 session 推到背景繼續執行
You: /background 繼續完成這個重構，我去做別的事

# 之後用 /tasks 查看所有背景任務
You: /tasks

Background sessions:
  [1] refactoring-auth     running  (started 5m ago)
  [2] security-audit       done     ✓

讓 Claude 自動分工

直接告訴 Claude 任務太大，讓它自己決定如何分工：

互動模式 
You: 我需要同時做三件事：
1. 重構 src/auth/ 使用新的 JWT 格式
2. 為 src/api/ 所有 endpoint 補上 input validation
3. 更新 README 反映新的 API 格式

請並行處理，不要互相干擾。

Claude: 好，我會派出三個 subagent 分別處理：
  → subagent-1: 處理 src/auth/ JWT 重構
  → subagent-2: 處理 src/api/ validation
  → subagent-3: 更新文件
  主代理等待所有任務完成後匯整。

Worktree 隔離（避免衝突）

多個 subagent 同時修改檔案可能產生衝突。 用 --worktree 讓每個 subagent 在獨立的 git worktree 工作：

互動模式 
# 每個 subagent 在獨立分支工作
You: 用 worktree 模式並行重構 auth 和 api 模組
ℹ️
什麼時候用多 Agent？

任務可以獨立分割時最有效（各自修改不同檔案）。若任務有依賴順序（A 完成後才能做 B），串行執行反而更安全。

查看所有 Agent 狀態

互動模式 
You: /tasks

Active tasks:
  [1] security-audit   running   Bash: running pytest...
  [2] doc-update       done      ✓ README.md updated

You: /agents

Subagent registry:
  orchestrator  (main)
  agent-a       working on src/auth/
  agent-b       working on src/api/
💡
費用注意

每個 subagent 都是獨立的 Claude API 呼叫，費用會倍增。用多 agent 前先確認任務真的能並行獲益。簡單的順序任務用單一 agent 就好。
