第 8 章 · Part 3：設定與記憶

Memory.md

Claude 的長期記憶——不是你寫的，是它在工作過程中自己學到的。跨對話、跨 session，讓 Claude 越來越了解你。

CLAUDE.md vs Memory.md

這兩個東西很容易搞混，關鍵差異在於誰來更新：

CLAUDE.md Memory.md
更新者 你（手動編輯） Claude（自動累積）
內容類型 固定規則與偏好 對話中發現的事實
典型內容 「回答請用繁體中文」 「Porter 喜歡用 PowerShell」
結構 你自己設計 Claude 自動整理
位置 ~/.claude/CLAUDE.md 依版本有所不同（見下方）
適用範圍 你設定的範圍 所有對話

三層記憶架構

Claude Code 的記憶系統分三個層次，由持久度排列：

1
CLAUDE.md — 顯式記憶
你手動撰寫的規則和設定。最可靠、最精確。適合固定不變的規則。
2
Auto Memory（Memory.md）— 隱式記憶
Claude 自動從對話中學習並儲存的事實。跨 session 累積，無需你手動維護。
3
Session 對話歷史 — 即時記憶
目前對話的完整上下文。session 結束後不保留（除非摘要進入 Memory.md）。
Session 1 Session 2 Session 3
3. Session 對話
對話歷史 A
對話歷史 B
對話歷史 C
↓ Session 結束後，Claude 自動摘要重點寫入 Memory.md ↓
2. Memory.md
累積量少
記憶增厚
記憶豐富
1. CLAUDE.md
固定不變的規則（手動維護）

Auto Memory（自動記憶）

Claude Code v2.1.59 以上版本支援自動記憶功能，預設啟用。

工作原理：

  1. 每次 session 結束時，Claude 自動整理這次對話中發現的重要事實
  2. 儲存到 ~/.claude/projects/<project-hash>/memory/MEMORY.md
  3. 下次 session 開始時，自動載入前 200 行或 25KB 的記憶內容
  4. 隨時間累積，Claude 對你和你的專案越來越了解

Memory.md 的典型內容

Claude 會自動記錄這類型的資訊：

~/.claude/projects/.../memory/MEMORY.md（Claude 自動生成） 
# 使用者偏好
- 使用 Windows 11 + PowerShell（不是 bash）
- 回答偏好繁體中文
- 喜歡看到實際可執行的程式碼範例
- 不喜歡過多的解釋，直接給答案

# 專案相關
- 主要工作目錄：C:\VSCode_Proj\
- Obsidian vault 位置：C:\Obsidian\vault\
- 工作日誌路徑：C:\Obsidian\vault\工作日誌\YYYY-MM-DD.md
- 正在開發：Dify-based AI agent 系統

# 技術偏好
- 偏好 TypeScript over JavaScript
- 使用 Vitest（不是 Jest）
- 部署環境：Docker + AWS EC2
- 資料庫：PostgreSQL

# 注意事項
- 使用者公司域名：gyro.com.tw
- API 測試環境：http://localhost:3000

清除記憶

互動模式 
You: /memory
# 選擇對應的檔案，手動刪除不需要的內容

# 或完全清除 auto memory
You: 請清除所有 auto memory 的內容

關閉自動記憶

如果不想讓 Claude 自動記憶，可以在設定中關閉：

互動模式 
You: /config
# 找到 "Auto Memory" 設定，切換為 disabled

或在 ~/.claude/settings.json 中加入：

~/.claude/settings.json 
{
  "autoMemoryEnabled": false
}

最佳實踐

  • 不要同時用兩套系統記同樣的事——固定規則放 CLAUDE.md，動態事實讓 Memory.md 自動維護
  • 定期清理 Memory.md——過時的記憶（舊的 API endpoint、已廢棄的設定）會干擾 Claude
  • 高優先規則寫在 CLAUDE.md——Memory.md 的內容不如 CLAUDE.md 可靠，重要規則永遠放 CLAUDE.md
  • 主動告知重要事實——不要等 Claude 自己發現，直接說「幫我記住 X」效率更高
💡
小結：如何分工

CLAUDE.md = 你的規則手冊（你維護）
Memory.md = Claude 的學習筆記（它自己維護）
兩者互補，讓每次對話都從最佳起點開始。
