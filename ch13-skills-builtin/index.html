第 13 章 · Part 5：Skills

使用內建 Skills

一個 Slash Command，啟動完整的工作流程。

最常用的內建 Skills

/review — 程式碼審查

對目前 diff 或指定檔案做五軸審查：正確性、可讀性、架構、安全性、效能。

互動模式 
# 審查目前的 git diff
You: /review

# 指定深度
You: /review --effort high

# 自動修復找到的問題
You: /review --fix

# 發佈為 PR inline comment（需設定 GitHub）
You: /review --comment

/build — 逐步建置

讓 Claude 按照「建置 → 測試 → 修正」循環執行，直到通過或你叫停。

互動模式 
# 建置並確保測試通過
You: /build

# 指定目標
You: /build 完成 user profile API 的實作

/spec — 撰寫規格文件

在動手寫程式碼之前，先產出結構化的規格文件（spec-driven development）。

互動模式 
You: /spec 設計一個支援多租戶的訂閱計費系統

# Claude 會產出：
# - 功能需求
# - 資料模型
# - API 設計
# - 邊界情況與限制
# 確認 spec 後再開始實作

/plan — 任務規劃

把複雜任務拆解成可執行的步驟清單，設定驗收條件。

互動模式 
You: /plan 把 Express.js 後端遷移到 Fastify，不中斷現有 API

/ship — 上線前檢查清單

上線前的系統性檢查：測試、型別、安全性、效能、文件。

互動模式 
You: /ship

# 並行執行多個專責 persona 檢查：
# ✓ 測試通過
# ✓ 型別無錯誤
# ✓ 無已知安全漏洞
# ✓ 效能無明顯瓶頸
# ✓ CHANGELOG 已更新
# → Go / No-Go 結論

/simplify — 程式碼簡化

在不改變行為的前提下，精簡程式碼結構。

互動模式 
# 簡化目前修改的程式碼
You: /simplify

# 指定目標
You: /simplify src/utils/date.ts

/deep-research — 深度研究

多來源網路搜尋 → 交叉驗證 → 產出引用報告。

互動模式 
You: /deep-research Claude Code 與 GitHub Copilot Workspace 的功能比較

使用 Tips

💡 加參數
多數 Skills 支援 --effort low/medium/high 控制深度
🎯 加說明
/review 重點關注 SQL injection 風險
📖 查 Skill 說明
/help review 顯示詳細說明與參數
🔗 組合使用
先 /spec 確認方向，再 /build，最後 /ship
💡
Skills 也能自動觸發

你不一定要輸入 Slash Command。在對話中說「幫我審查這個 PR 的安全性」，如果對應 Skill 的 TRIGGER 條件符合，Claude 會自動套用該 Skill 的執行流程。
