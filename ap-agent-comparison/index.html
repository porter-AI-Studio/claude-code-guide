附錄 D · 工具對比

AI 代理工具大比拼 (Claude Code vs Cursor)

評測獨立終端代理（Claude Code）與編輯器內置型代理（Cursor / Antigravity）的架構底層、上下文能力與開發協作工作流。

一、 兩大 AI 輔助開發工具路線對比

目前的 AI 程式設計工具市場，主要分化為兩大主流技術路線：

比較維度 CLI 獨立代理型 (如 Claude Code) IDE 內嵌型 (如 Cursor / Antigravity IDE)
核心形態 終端命令列 (CLI) 進程，獨立於編輯器。 深度整合於 VS Code / IntelliJ 的圖形化編輯器環境。
互動方式 基於文字的對話與指令審核工作流，以終端作為控制中樞。 側邊欄對話、行內編輯 (Cmd+K)、程式碼補全 (Tab) 等多模態 UI。
自主權限 極高。AI 可以自主派生命令、執行編譯與測試，直到達成目標。 中等。除 Composer 代理模式外，多數功能仍依賴人類手動點擊 Accept。
主要優勢 速度極快、對複雜重構與自動化測試任務的執行力極強。 視覺化程式碼差異對比 (Diff)、編輯無縫銜接、Tab 自動補全體驗極佳。

二、 上下文 (Context) 獲取能力的差異

AI 代理的表現好壞，高達 80% 取決於它能獲取到多精準的程式碼上下文：

  • Cursor 的上下文獲取：依賴其在後台運行的 Ctags/Language Server 索引，或是專有的向量索引 (Vector Database)。當你在 Chat 中輸入 @Codebase 時，它透過語意搜尋拉取相關的程式碼片段。
  • Claude Code 的上下文獲取：深度依賴專案的 Git 狀態與檔案系統。它會自動讀取 git diff、檢視 git status 或是利用 grep 工具遍歷專案。

這導致兩者在不同任務上的表現各異：

  • 對於全新且龐大的代碼庫，Cursor 的 `@Codebase` 能迅速給出框架層面的語意理解。
  • 對於需要頻繁修改並立刻跑測試驗證的專案，Claude Code 藉由本地真實命令行的反饋，在精確度與修復速度上完勝。

三、 Agentic Loop (代理循環) 的效率分析

Agentic Loop 指的是 AI 代理自主發現問題 ➔ 寫程式 ➔ 跑測試 ➔ 看到 Error ➔ 自動修改 ➔ 再跑測試的「自愈循環」。

  • Cursor 的 Loop：主要採用人類引導。AI 寫完代碼後，需要人類工程師點擊「Save」，然後在終端手動執行編譯，並把報錯複製回對話框。
  • Claude Code 的 Loop：自主且連續。當你給出「幫我修復這個測試錯誤」的指令後，它可以自己運行 npm run test，捕捉 stderr 輸出，修改代碼後再次執行測試，直到測試完全綠燈才回報給人類。這極大地解放了開發者的時間。

四、 混合使用：黃金協作工作流最佳實踐

身為一個高效能的 AI 原生工程師，你不需要「二選一」，而應該**將兩者的長處結合**，打造出黃金協作工作流：

💡
黃金協作三部曲
  1. 使用 Cursor 行內編輯與補全：在編寫日常代碼、調整 UI 樣式或編寫單一函數時，利用 Cursor 的 Tab 補全與行內 Cmd+K，享受最流暢的圖形編輯體驗。
  2. 使用 Claude Code 處理複雜重構與測試：當遇到需要跨 5、6 個檔案修改，或者依賴單元測試（Unit Test）來驗證的 bug 時，在終端呼叫 claudecode，將該任務交付給它自主循環修復。
  3. 共同遵循 CLAUDE.md：在專案根目錄放置 CLAUDE.md（見本書第 6 章），記錄專案的編譯、測試指令。不論是 Claude Code 還是 Cursor，都能讀取此定義，確保兩大工具不會在執行指令時打架。

五、 選型決策建議

在進行日常工作時，您可以參考以下決策路徑：

  • 若任務是「設計精美的 Web 前端 UI 網頁」：優先使用 Cursor / VS Code，因為能隨時雙螢幕預覽 HTML/CSS 的渲染結果。
  • 若任務是「重構複雜的後端 API、修正難纏的 Bug 或是撰寫單元測試」：優先在終端呼叫 Claude Code，因為它在 CLI 執行測試的自愈速度極快。
  • 若任務是「大範圍的代碼閱讀與影響力分析」：可以搭配 CodeGraph MCP 伺服器，結合 Claude Code 或 Cursor，大幅節省 Token 的支出。
