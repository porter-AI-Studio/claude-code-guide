第 11 章 · Part 4：Hooks

Hooks 安全性應用

CLAUDE.md 規則靠 Claude 自覺，Hooks 是技術層面的強制執行。攔截危險指令、記錄審計日誌、送出通知——這些都不需要 Claude 的配合。

為什麼需要安全性 Hooks？

你可以在 CLAUDE.md 寫「不要執行 rm -rf」，Claude 通常會遵守——但這依賴 Claude 正確理解並記住你的規則。在以下情況，這樣的「軟性約束」可能失效：

  • 多步驟自動化任務中，Claude 誤判了安全性
  • 使用 --dangerously-skip-permissions 模式跑 batch 任務
  • 你想確保無論如何某些指令都不會被執行

Hooks 讓你在 shell 層面攔截——Claude 說要執行什麼，Hook 腳本先審查，不通過就直接擋下來，跟 Claude 的判斷無關。

阻擋危險指令

使用 PreToolUse 事件搭配 matcher: "Bash"，在每個 Bash 指令執行前進行安全檢查：

~/.claude/settings.json 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/hooks/security-check.sh"
          }
        ]
      }
    ]
  }
}
~/.claude/hooks/security-check.sh 
#!/bin/bash
INPUT=$(cat)
COMMAND=$(echo "$INPUT" | python3 -c "import sys,json; print(json.load(sys.stdin)['tool_input']['command'])")

DANGEROUS_PATTERNS=("rm -rf /" "DROP TABLE" "git push --force" "format c:")

for pattern in "${DANGEROUS_PATTERNS[@]}"; do
  if echo "$COMMAND" | grep -qi "$pattern"; then
    echo '{"decision":"block","reason":"Dangerous command blocked: '"$pattern"'"}' >&2
    exit 2
  fi
done

exit 0

腳本邏輯說明：

  1. 從 stdin 讀取 JSON，取出 tool_input.command
  2. 逐一比對危險關鍵字清單
  3. 若匹配，輸出 JSON 到 stderr 並以 exit code 2 阻擋執行
  4. 若安全，exit code 0 允許通過

執行腳本前，記得加上執行權限：

Terminal 
chmod +x ~/.claude/hooks/security-check.sh

進階：Python 版 + 保護敏感檔案

Python 版安全守衛更強大——同時保護 .env、金鑰檔案等敏感資源。 更重要的是，它使用 permissionDecision: "deny" 格式輸出阻擋決策： 即使使用者開啟 --dangerously-skip-permissions，這個 Hook 也無法被繞過。

~/.claude/hooks/security-guard.py 
#!/usr/bin/env python3
import json, sys

data = json.load(sys.stdin)
tool = data.get("tool_name", "")
tool_input = data.get("tool_input", {})

def deny(reason):
    # permissionDecision: "deny" 比 exit 2 更強——bypass 模式也有效
    print(json.dumps({
        "hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": "deny",
            "permissionDecisionReason": reason,
        }
    }))
    sys.exit(0)  # exit 0，但 JSON 裡宣告 deny

# 保護敏感檔案，不允許寫入
if tool in ("Write", "Edit", "MultiEdit"):
    path = tool_input.get("file_path", "")
    sensitive = [".env", ".pem", ".key", "credentials", "id_rsa", "id_ed25519"]
    if any(s in path for s in sensitive):
        deny(f"拒絕修改敏感檔案：{path}")

# 阻擋危險 Shell 指令
if tool == "Bash":
    command = tool_input.get("command", "")
    dangerous = ["rm -rf /", "git push --force", "DROP TABLE", "DROP DATABASE", "mkfs"]
    if any(p.lower() in command.lower() for p in dangerous):
        deny(f"阻擋高風險指令：{command[:80]}")

sys.exit(0)
~/.claude/settings.json（Python 版） 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash|Write|Edit|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "python3 ~/.claude/hooks/security-guard.py"
          }
        ]
      }
    ]
  }
}
ℹ️
permissionDecision: "deny" vs exit 2

exit 2 是標準阻擋方式，但在 --dangerously-skip-permissions 模式下會被略過。
permissionDecision: "deny"（透過 stdout JSON）是更底層的阻擋——CC 在協定層拒絕，任何 flag 都無法繞過。
安全性要求高的場景（CI/CD、自動化腳本）請優先使用 Python + JSON 格式。

改寫指令而非阻擋

PreToolUse Hook 除了阻擋，還可以用 updatedInput 欄位 靜默修改工具的輸入——Claude 感知不到，使用者也不需要確認，但危險性消除了。

經典應用：把 git push --force 自動升級為更安全的 --force-with-lease。

~/.claude/hooks/safer-git-push.py 
#!/usr/bin/env python3
import json, sys

data = json.load(sys.stdin)
tool_input = data.get("tool_input", {})
command = tool_input.get("command", "")

# git push --force → 靜默改為 --force-with-lease
if ("git push" in command
        and "--force" in command
        and "--force-with-lease" not in command):
    new_cmd = command.replace("--force", "--force-with-lease")
    print(json.dumps({
        "hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": "allow",
            "updatedInput": {**tool_input, "command": new_cmd},
            "additionalContext": "已自動將 --force 改為 --force-with-lease 以保護遠端分支。",
        }
    }))
    sys.exit(0)

sys.exit(0)
💡
updatedInput 的應用場景

除了 git push，同樣的模式可以用在：自動加上 --dry-run（讓 Claude 先預覽再執行）、把 rm 替換成 mv ... ~/.trash/（軟刪除）、自動在 SQL 查詢加上 LIMIT 100 防止全表掃描。

通知 Hook

當 Claude 完成任務時，發送 Windows 桌面通知：

~/.claude/hooks/notify.ps1 
# 從 stdin 讀取資料（Stop 事件）
$data = $input | ConvertFrom-Json

# 發送 Windows 桌面通知
Add-Type -AssemblyName System.Windows.Forms
$notify = New-Object System.Windows.Forms.NotifyIcon
$notify.Icon = [System.Drawing.SystemIcons]::Information
$notify.Visible = $true
$notify.BalloonTipTitle = "Claude Code"
$notify.BalloonTipText = "任務完成！Session: $($data.session_id)"
$notify.ShowBalloonTip(3000)

Start-Sleep -Milliseconds 3500
$notify.Dispose()
~/.claude/settings.json（加入通知） 
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "powershell -NonInteractive -File ~/.claude/hooks/notify.ps1"
          }
        ]
      }
    ]
  }
}

審計日誌

記錄每一條 Claude 執行過的 Bash 指令，方便事後查核：

~/.claude/hooks/audit-log.sh 
#!/bin/bash
INPUT=$(cat)
COMMAND=$(echo "$INPUT" | python3 -c "import sys,json; d=json.load(sys.stdin); print(d['tool_input'].get('command',''))")
SESSION=$(echo "$INPUT" | python3 -c "import sys,json; print(json.load(sys.stdin).get('session_id','unknown'))")
TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
LOG_FILE=~/.claude/audit.log

echo "[$TIMESTAMP] [$SESSION] $COMMAND" >> "$LOG_FILE"
exit 0
~/.claude/settings.json（PostToolUse 審計） 
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/hooks/audit-log.sh"
          }
        ]
      }
    ]
  }
}

日誌格式範例：

~/.claude/audit.log 
[2026-06-04 14:35:22] [sess_abc123] ls -la
[2026-06-04 14:35:45] [sess_abc123] npm run build
[2026-06-04 14:36:10] [sess_abc123] git status

Stop 驗收守衛

你有沒有遇過 Claude 說「完成了！」但 TypeScript 還在噴錯、測試還在失敗的情況？ 用 Stop Hook 可以在 Claude 宣告任務完成之前強制做驗證——不通過就讓它繼續修。

~/.claude/hooks/verify-on-stop.sh 
#!/bin/bash
INPUT=$(cat)

# 防止無限迴圈：stop_hook_active 為 true 代表已由 Stop hook 觸發過
IS_ACTIVE=$(echo "$INPUT" | python3 -c "import sys,json; print(json.load(sys.stdin).get('stop_hook_active', False))")
[ "$IS_ACTIVE" = "True" ] && exit 0

PROJECT_DIR="$CLAUDE_PROJECT_DIR"
[ -z "$PROJECT_DIR" ] && PROJECT_DIR="$(pwd)"
cd "$PROJECT_DIR" || exit 0

# TypeScript 型別檢查
if ! npx tsc --noEmit 2>/dev/null; then
  echo '{"decision":"block","reason":"TypeScript 型別錯誤，請修正後再完成任務。"}'
  exit 0
fi

# 執行測試（若有）
if [ -f "package.json" ] && grep -q '"test"' package.json; then
  if ! npm test --silent 2>/dev/null; then
    echo '{"decision":"block","reason":"測試未通過，請修正後再完成任務。"}'
    exit 0
  fi
fi

exit 0
~/.claude/settings.json（Stop 驗收） 
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/hooks/verify-on-stop.sh",
            "timeout": 120
          }
        ]
      }
    ]
  }
}
⚠️
stop_hook_active — 防止無限迴圈必讀

Stop Hook 阻擋後，CC 把原因告知 Claude 讓它修正。修正完成後再次觸發 Stop → 再次執行 Hook → 再次阻擋……形成無限迴圈。
解法：腳本開頭檢查 stop_hook_active 欄位，若為 true 代表這次是由 Hook 觸發的二次結束，直接 exit 0 放行。

PermissionRequest Hook

PermissionRequest 事件在 Claude 請求執行需要使用者確認的操作時觸發。你可以用 Hook 自動批准安全的操作、攔截高風險的操作：

~/.claude/settings.json 
{
  "hooks": {
    "PermissionRequest": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/hooks/auto-approve.sh"
          }
        ]
      }
    ]
  }
}
~/.claude/hooks/auto-approve.sh 
#!/bin/bash
INPUT=$(cat)
TOOL=$(echo "$INPUT" | python3 -c "import sys,json; print(json.load(sys.stdin).get('tool_name',''))")

# 自動批准唯讀操作
SAFE_TOOLS=("Read" "Glob" "Grep" "WebSearch" "WebFetch")

for tool in "${SAFE_TOOLS[@]}"; do
  if [ "$TOOL" = "$tool" ]; then
    echo '{"decision":"approve"}'
    exit 0
  fi
done

# 其他操作讓 Claude 繼續詢問使用者
exit 0

偵測 API Key 洩漏

前面的 security-guard.py 保護的是敏感檔案路徑（.env、.pem）。 這個腳本則進一步掃描寫入的檔案內容——偵測常見 API Key 前綴（sk-、ghp_、AKIA 等）， 即使 Claude 把金鑰寫進看起來無害的 .ts 或 .json 檔案，一樣擋下來。

~/.claude/hooks/detect-api-keys.py 
#!/usr/bin/env python3
import json, sys

data = json.load(sys.stdin)
tool = data.get("tool_name", "")
tool_input = data.get("tool_input", {})

def deny(reason):
    print(json.dumps({
        "hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": "deny",
            "permissionDecisionReason": reason,
        }
    }))
    sys.exit(0)

if tool in ("Write", "Edit", "MultiEdit"):
    content = tool_input.get("new_content", tool_input.get("content", ""))
    for edit in tool_input.get("edits", []):
        content += edit.get("new_string", "")

    prefixes = ["sk-", "ghp_", "AKIA", "AIza", "ya29.", "xoxb-", "xoxp-"]
    found = [p for p in prefixes if p in content]
    if found:
        deny("偵測到 API Key 格式字串（" + ", ".join(found) + "），請改用環境變數。")

sys.exit(0)
~/.claude/settings.json（detect-api-keys） 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit|MultiEdit",
        "hooks": [
          {
            "type": "command",
            "command": "python3 ~/.claude/hooks/detect-api-keys.py"
          }
        ]
      }
    ]
  }
}

保護 main 分支

在 PreToolUse 攔截 Bash 工具，偵測到 git push ... main 或 master 時直接以 exit 2 阻擋，強制走 feature branch + PR 流程。

~/.claude/hooks/protect-main-branch.sh 
#!/bin/bash
INPUT=$(cat)
COMMAND=$(echo "$INPUT" | python3 -c "import sys,json; print(json.load(sys.stdin).get('tool_input',{}).get('command',''))")

if echo "$COMMAND" | grep -q "git push"; then
  if echo "$COMMAND" | grep -qE "(main|master)"; then
    echo '{"decision":"block","reason":"禁止直接 push 到 main/master，請建立 feature branch 並開 PR。"}' >&2
    exit 2
  fi
fi

exit 0
~/.claude/settings.json（protect-main-branch） 
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "~/.claude/hooks/protect-main-branch.sh"
          }
        ]
      }
    ]
  }
}

⚠️
Hook 腳本的安全性

Hook 腳本本身也可能成為安全漏洞：確保腳本只有你自己可以寫入（chmod 700）、不要在腳本中 hardcode 密碼或 API key、避免直接將 stdin 內容插入 shell 指令（使用 python3 解析 JSON 而非 eval）。
