各模型適用情境

🐇 Haiku 4.5 — 用在這些場合

  • 快速問答（「這個函式做什麼？」「這個錯誤是什麼意思？」）
  • 簡單的程式碼修改（改一個變數名、加一行 import）
  • 生成模板程式碼（boilerplate）
  • 程式碼格式化或整理
  • 需要大量呼叫 API 的自動化場景（成本考量）
  • CI/CD pipeline 中的輔助任務

🏆 Sonnet 4.6 — 日常主力（預設）

  • 複雜功能開發（多個檔案、邏輯複雜）
  • Bug 分析與修復（需要理解上下文）
  • 程式碼重構（保持行為不變的前提下改善結構）
  • 撰寫完整的測試套件
  • 程式碼審查（找潛在問題）
  • 99% 的日常開發任務

🧠 Opus 4.8 — 留給真正困難的任務

  • 系統架構設計（要考慮擴展性、維護性的大決策）
  • 難以重現的複雜 Bug（需要深度追蹤邏輯）
  • 效能優化分析（演算法層面的改善）
  • 安全性審計（找出深層漏洞）
  • 理解和重構年久失修的 legacy code
  • 需要多步驟推理的長期任務

費用估算範例

以一個中型功能開發任務為例（約 50k input + 5k output tokens）：

模型InputOutput合計
Haiku 4.5$0.05$0.025~$0.075
Sonnet 4.6$0.15$0.075~$0.225
Opus 4.8$0.25$0.125~$0.375

實際費用因 Prompt Cache 命中率而大幅降低。Claude Code 會自動快取重複的上下文（如 CLAUDE.md、常讀取的檔案），快取讀取費用約為一般費用的 10%。

實用建議

從 Sonnet 開始。它是最佳預設。當你發現任務太簡單不需要這麼強時，切到 Haiku 省錢；當 Sonnet 卡關時，升級到 Opus。下一章會教你怎麼切換。
